# 커밋 메시지 검증
커밋 메시지가 다음 구조를 만족하는지 판단하고 맞으면 통과, 충돌되는 사항이 있으면 중단한다.
```
커밋 헤더: 짧은 커밋 메시지

긴 커밋 메시지
```
긴 커밋 메시지는 선택 사항으로, 없어도 된다.

## 커밋 헤더
- feat: 기능 추가 목적
- fix: 기능 수정 목적
- docs: 단순히 문서 파일만 변경
- refactor: 기능은 동일하나, 코드 구조를 변경
- test: 주로 테스트 코드에 대한 작업

## 짧은 커밋 메시지
- 50자 내외
- 현재 커밋 사항에 대한 종합적인 메시지
- 명사로 끝낼 것. 예를 들어 "XXX 기능 수정", "XXX 테스트 코드 작성"처럼 간략화

## 긴 커밋 메시지 (Optional)
필요한 경우, 긴 커밋 메시지를 작성한다. 다음을 만족한다.
- dot 방식으로 나열
- 무엇을, 어떻게 했는지보다 '왜'에 집중하여 작성
- dot의 개수는 0개 - 3개 사이로 할 것
