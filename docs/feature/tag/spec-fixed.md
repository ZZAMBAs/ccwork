# 태그 기능 상세 요구사항

## 문서 목적

이 문서는 `docs/feature/tag/spec-original.md`의 간단한 태그 기능 정의를 바탕으로 확정한 상세 요구사항이다.

원본 문서는 인코딩이 깨져 있지만, 다음 요구로 해석한다.

- 노트에 태그를 추가할 수 있다.
- 노트에 추가된 태그를 삭제할 수 있다.
- 노트에 추가된 태그 구성을 변경할 수 있다.
- 노트 상세 화면에서 태그 목록을 확인할 수 있다.
- 태그 단위로 노트를 모아 확인할 수 있다.
- 태그는 문자열로 관리한다.
- 중복 태그를 허용하지 않는다.
- 태그는 2자 이상이어야 한다.

## 핵심 방향

- 태그는 별도 리소스가 아니라 `Note` 객체 안의 `tags: string[]`로 저장한다.
- 태그 추가/삭제는 노트 편집 화면에서 수행한다.
- 원본의 태그 수정 요구는 전역 태그 이름 변경이 아니라, 노트별 태그 구성을 추가/삭제로 변경하는 의미로 해석한다.
- 전역 태그 이름 변경과 전역 태그 삭제는 제공하지 않는다.
- 태그 목록과 태그별 노트 모아보기는 저장된 노트들의 `tags` 값을 집계해서 만든다.
- 태그 탐색은 기존 노트 편집 화면과 분리된 `tags` 모드에서 제공한다.

## 데이터 모델

### Note 타입

`src/types/note.ts`의 `Note` 타입에 `tags`를 추가한다.

```ts
type Note = {
  id: string;
  title: string;
  content: string;
  createdAt: string;
  updatedAt: string;
  tags: string[];
};
```

### 태그 저장 방식

- 태그는 `Note.tags`에 문자열 배열로 직접 저장한다.
- 별도의 `tags` JSON Server 리소스는 만들지 않는다.
- 태그별 목록, 대표 표시명, 노트 수, 최근 저장일은 모두 저장된 `notes` 상태에서 파생한다.
- API 응답에 `tags`가 없으면 클라이언트에서 `[]`로 보정한다.
- 저장 요청에는 항상 `tags: string[]`를 포함한다.
- `db.json`의 기존 노트에는 `tags: []`를 추가하고, 예시 태그는 넣지 않는다.

### 타입 파일

- `src/types/note.ts`: `Note.tags` 추가
- `src/types/tag.ts`: 태그 집계와 태그 화면에서 사용할 파생 타입 추가

예상 타입:

```ts
type TagSummary = {
  key: string;
  label: string;
  count: number;
  latestUpdatedAt?: string;
};
```

## 태그 정규화와 비교

### 정규화

태그 입력값은 저장 전에 다음 규칙으로 정규화한다.

- 앞뒤 공백을 제거한다.
- 내부 연속 공백은 한 칸으로 축약한다.
- 대소문자 표기는 사용자가 입력한 값을 유지한다.
- `#`는 제거하지 않는다.
- 정규화된 저장값을 화면에도 그대로 표시한다.

예:

- `React  Query` -> `React Query`
- `#React  Query` -> `#React Query`
- `# #` -> `# #`

### 비교 키

중복 판단, 태그 집계, 검색 매칭에는 비교 키를 사용한다.

- 공백 정규화 후 소문자로 변환한다.
- `#`는 일반 문자로 포함한다.
- `#React`와 `React`는 서로 다른 태그다.
- `React Query`, `React  Query`, `react query`는 같은 태그다.

예:

- `React` -> `react`
- `REACT` -> `react`
- `#React` -> `#react`
- `React Query` -> `react query`

## 태그 유효성 규칙

### 허용 문자

정규화 후 태그에는 다음 문자만 사용할 수 있다.

- 완성형 한글 음절
- ASCII 영문자 `A-Z`, `a-z`
- ASCII 숫자 `0-9`
- 공백
- 하이픈 `-`
- 언더스코어 `_`
- 해시 `#`

허용 문자 오류 메시지:

```text
한글, 영문, 숫자, 공백, -, _, #만 사용할 수 있습니다
```

### 길이 제한

- 정규화 후 최소 2자 이상이어야 한다.
- 정규화 후 최대 20자 이하여야 한다.
- `#`은 1자라서 허용하지 않는다.
- `##`은 2자라서 허용한다.

오류 메시지:

- 최소 길이: `2자 이상 입력하세요`
- 최대 길이: `20자 이하로 입력하세요`

### 기호만 있는 태그

- 허용 문자와 길이 조건을 만족하면 기호만 있는 태그도 허용한다.
- `--`, `__`, `##`, `# #` 모두 허용한다.
- 한글/영문/숫자를 최소 1개 포함해야 한다는 규칙은 두지 않는다.

### 빈 입력

- 공백만 있는 입력은 정규화 후 빈 값이므로 오류 없이 무시한다.
- 쉼표 분리 후 빈 조각도 오류 없이 무시한다.
- 전체 입력이 빈 조각뿐이면 아무 것도 추가하지 않는다.

### 기존 저장 데이터의 유효하지 않은 태그

- 태그 집계에서는 유효하지 않은 저장 태그를 무시한다.
- 노트 편집 화면에서는 기존 유효하지 않은 태그도 칩으로 그대로 보여준다.
- 유효하지 않은 기존 태그 칩에는 가벼운 경고 스타일을 적용한다.
- 유효하지 않은 기존 태그가 남아 있으면 저장 시 인라인 오류로 막는다.
- 유효하지 않은 기존 태그도 삭제 버튼을 제공해서 사용자가 제거할 수 있게 한다.

## 태그 대표 표시명

태그 목록과 자동완성에서 보이는 대표 표시명은 저장된 전체 노트의 태그를 집계해서 계산한다.

- 같은 비교 키를 가진 태그들을 하나의 태그로 묶는다.
- 가장 많이 사용된 표기를 대표 표시명으로 사용한다.
- 사용 횟수가 동률이면 가장 최근에 저장된 표기를 사용한다.
- 대표 표시명의 casing은 선택된 표기를 따른다.
- 대표 표시명의 공백은 항상 정규화된 한 칸 공백을 사용한다.
- 저장 전 임시 편집 상태는 대표 표시명 계산에 반영하지 않는다.

예:

- `ReAcT`, `REACT`, `React`는 같은 태그다.
- `React`가 가장 많이 사용되었다면 대표 표시명은 `React`다.
- `React`와 `REACT` 사용 횟수가 같다면 더 최근에 저장된 표기를 대표 표시명으로 사용한다.

## 태그 집계

태그 집계 결과에는 다음 정보를 포함한다.

- 비교 키
- 대표 표시명
- 포함 노트 수
- 최근 저장일

### 포함 노트 수

- 해당 태그 비교 키를 가진 노트 수를 센다.
- 같은 노트 안에 같은 비교 키의 태그가 중복 입력된 경우에는 하나로 취급한다.

표시 형식:

```text
3개 노트
```

### 최근 저장일

- 해당 태그가 붙은 노트들 중 가장 최신 `updatedAt`을 사용한다.
- 날짜 비교는 `Date`로 파싱해서 수행한다.
- `updatedAt`이 없거나 잘못된 날짜인 노트도 집계에는 포함한다.
- 잘못된 날짜는 정렬에서는 가장 오래된 값으로 취급한다.
- 날짜가 없거나 잘못된 경우에는 `최근 저장 ...` 영역 자체를 표시하지 않는다.

표시 형식:

```text
최근 저장 YYYY.MM.DD HH:mm
```

날짜 표시 방식은 기존 앱의 날짜 표시 방식이 있으면 우선 맞춘다. 기존 방식이 없으면 `YYYY.MM.DD HH:mm`을 사용한다.

## 태그 입력 UI

### 위치

노트 편집 화면에서 태그 입력 영역은 제목 입력 아래, 본문 입력 위에 배치한다.

### 구성

- 태그 입력 필드
- 추가 버튼
- 현재 노트에 추가된 태그 칩 목록
- 인라인 오류 메시지 영역
- 자동완성 드롭다운

### 추가 방식

- `Enter` 또는 추가 버튼으로 태그를 추가한다.
- 쉼표가 포함된 입력은 `Enter` 또는 추가 버튼 클릭 시점에만 분리한다.
- 입력 중 쉼표를 입력하는 순간 자동으로 칩을 만들지 않는다.
- 태그 추가 성공 후 입력창 포커스를 유지한다.
- 태그 입력창이 비어 있을 때 `Backspace`를 눌러도 마지막 태그 칩을 삭제하지 않는다.

### 쉼표 일괄 추가

예:

```text
React, TypeScript ,  Vite
```

처리 결과:

- `React`
- `TypeScript`
- `Vite`

규칙:

- 쉼표로 나눈 각 조각에 동일한 정규화와 검증을 적용한다.
- 빈 조각은 무시한다.
- 하나라도 유효하지 않으면 아무 태그도 추가하지 않는다.
- 전체 입력을 유지한 채 첫 번째 오류를 인라인으로 표시한다.
- 입력 묶음 안에서 중복되는 태그는 하나로 합친다.
- 입력 묶음 안의 중복 표기는 첫 번째 유효 표기를 사용한다.

예:

```text
React, react, REACT
```

처리 결과:

- `React` 1개만 추가

### 중복 처리

#### 전체 태그 기준 중복

- 이미 저장된 전체 태그와 같은 비교 키로 입력해도 오류가 아니다.
- 새 전역 태그를 만들지 않고 같은 태그로 재사용된다.
- 별도 태그 엔티티가 없으므로 실제로는 현재 노트의 `tags`에 문자열이 저장된다.

#### 현재 노트 안의 중복

- 현재 노트에 이미 있는 태그와 같은 비교 키를 다시 입력하면 중복 추가하지 않는다.
- 오류 메시지는 표시하지 않는다.
- 입력값만 비운다.
- 기존 태그 칩은 그대로 유지한다.

#### 직접 입력과 자동완성 선택의 표시

- 자동완성에서 기존 태그를 선택하면 대표 표시명을 그대로 칩에 추가한다.
- 직접 입력이 기존 태그와 같은 비교 키로 매칭되어도 현재 노트의 칩에는 사용자가 방금 입력한 표기를 보여주고 저장한다.
- 직접 입력 새 태그는 입력 casing을 유지하고 공백만 정규화한다.

### 최대 개수

- 노트당 최대 태그 개수는 5개다.
- 5개에 도달하면 입력 필드와 추가 버튼을 비활성화한다.
- 도움 문구를 표시한다.

도움 문구:

```text
태그는 최대 5개까지 추가할 수 있습니다
```

- 기존 태그를 삭제하면 입력 필드와 추가 버튼을 다시 활성화한다.
- 최대 개수 검사는 정규화와 중복 제거 후 실제로 새로 추가될 태그 수를 기준으로 한다.

예:

- 현재 태그: `React`, `Vite`, `CSS`, `UI`
- 입력: `react, TypeScript`
- `react`는 현재 노트에 이미 있으므로 실제 추가는 `TypeScript` 1개다.
- 결과 개수는 5개이므로 허용한다.

### 유효성 오류 표시

- 태그 입력 필드 바로 아래에 짧은 인라인 오류 메시지를 표시한다.
- 오류가 있는 동안 저장을 막는다.
- 오류 메시지는 원인별로 구체적으로 나눈다.
- 추가 시점에는 반드시 검증한다.
- 입력 중에는 오류가 이미 표시된 상태일 때만 재검사해서 메시지를 갱신하거나 해제한다.

주요 오류 메시지:

- `2자 이상 입력하세요`
- `20자 이하로 입력하세요`
- `한글, 영문, 숫자, 공백, -, _, #만 사용할 수 있습니다`
- `태그는 최대 5개까지 추가할 수 있습니다`

### 추가되지 않은 태그 입력

태그 입력창에 텍스트가 남아 있는데 사용자가 저장 버튼을 누르면 자동으로 태그를 추가하지 않는다.

처리:

- 저장하지 않는다.
- 앱 내부 안내 모달을 보여준다.
- 모달은 `확인` 버튼 하나만 가진다.
- 사용자가 직접 태그를 추가하거나 입력값을 지운 뒤 다시 저장해야 한다.

문구:

- 제목: `추가되지 않은 태그가 있습니다`
- 본문: `태그 입력창의 내용을 추가하거나 지운 뒤 저장해 주세요.`
- 버튼: `확인`

## 태그 칩

### 편집 화면

- 태그 칩은 표시용이다.
- 칩 자체 클릭에는 동작을 두지 않는다.
- 삭제 버튼으로만 태그를 제거한다.
- 삭제 버튼은 hover 시에만 보이게 한다.
- 키보드 접근성을 위해 삭제 버튼은 항상 DOM에 존재한다.
- 마우스 hover 또는 삭제 버튼 focus 시 삭제 버튼을 표시한다.
- 긴 태그 텍스트는 칩 내부에서 한 줄 말줄임 처리한다.
- 칩에는 최대 너비를 둔다.

### 사이드바 노트 아이템

- 노트 아이템에도 태그를 표시한다.
- 최대 2개 칩만 표시한다.
- 나머지는 `+N`으로 표시한다.
- 긴 태그 텍스트는 한 줄 말줄임 처리한다.

### 태그 상세 노트 카드

- 노트 카드에는 해당 노트의 전체 태그를 모두 표시한다.
- 현재 보고 있는 태그도 포함한다.
- 현재 태그를 별도로 강조하지 않는다.
- 모든 태그 칩은 같은 스타일로 표시한다.

## 자동완성

### 데이터 기준

- 저장된 전체 노트의 태그 집계 결과를 기반으로 한다.
- 새 노트 생성 중에도 기존 전체 노트의 태그를 기반으로 자동완성을 제공한다.
- 저장 전 임시 태그는 자동완성에 반영하지 않는다.
- 현재 노트에 이미 추가된 태그는 자동완성 제안에서 제외한다.

### 매칭

- 대소문자 무시 prefix 검색을 사용한다.
- `#`도 일반 문자로 prefix 매칭한다.
- 한글 초성 검색은 지원하지 않는다.

예:

- `rea` -> `React` 매칭
- `act` -> `React` 매칭 안 됨
- `#R` -> `#React` 매칭
- `R` -> `#React` 매칭 안 됨

### 표시와 정렬

- 최대 3개만 보여준다.
- 자동완성 항목에는 태그명만 표시한다.
- 별도 스크롤 없이 표시한다.
- 짧게 일치하는 태그를 우선한다.
- 길이가 같으면 사용 빈도 높은 순으로 정렬한다.
- 사용 빈도도 같으면 최근 사용 순으로 정렬한다.

예:

- 입력 `rea`
- `React`가 `React Query`보다 먼저 표시된다.

### 상호작용

- 입력창 아래 드롭다운으로 표시한다.
- 마우스 클릭으로 선택할 수 있다.
- 키보드 방향키로 이동하고 `Enter`로 선택할 수 있다.
- `Escape`는 자동완성 목록만 닫고 입력값은 유지한다.
- 입력창 밖을 클릭하면 자동완성 목록만 닫고 입력값은 유지한다.
- 자동완성 항목을 선택하면 즉시 태그 칩으로 추가한다.
- 선택 후 다시 추가 버튼을 누르게 하지 않는다.

## 저장과 변경 상태

### 저장 흐름

- 태그는 제목, 본문과 같은 노트 저장 데이터의 일부다.
- 태그만 변경해도 저장 버튼으로 저장한다.
- 태그 변경 저장 시에도 `updatedAt`을 갱신한다.
- 노트 생성/수정 시각 생성은 기존 `src/api/notes.ts` 흐름을 따른다.
- Context 상태는 API 요청 성공 후 응답 값을 기준으로 갱신한다.

### 저장 버튼 활성화

저장 버튼은 다음 중 하나를 만족할 때만 활성화한다.

- 마지막 저장 상태 대비 제목, 본문, 태그 중 하나라도 변경됨
- 태그 입력창에 아직 추가되지 않은 텍스트가 남아 있음

변경사항이 없고 미추가 태그 입력도 없으면 저장 버튼은 비활성화한다.

### 저장 성공

저장 성공 후:

- dirty 상태를 `false`로 만든다.
- 태그 입력값을 초기화한다.
- 태그 오류 상태를 초기화한다.
- 자동완성 상태를 초기화한다.

### 저장 실패

저장 실패 시:

- 제목, 본문, 태그 입력값을 그대로 유지한다.
- dirty 상태를 그대로 유지한다.
- 기존 실패 처리처럼 `console.error`를 기록한다.
- 화면 오류 표시가 있으면 기존 흐름에 맞춰 노출한다.

### 새 노트 저장

- 기존 제목/본문 저장 검증 규칙을 유지한다.
- 기존 앱에서 제목/본문이 비어 있는 노트를 허용한다면 태그만 있는 노트도 허용한다.
- 기존 앱에서 제목/본문 필수 규칙이 있다면 그 규칙을 그대로 적용한다.

## 미저장 변경 보호

### dirty 판정

`NoteEditor`가 dirty 여부를 계산하고 `App`에 콜백으로 알려준다.

dirty 조건:

- 생성 중인 새 노트 또는 기존 노트 편집 중 제목이 마지막 저장 상태와 다름
- 본문이 마지막 저장 상태와 다름
- 태그 목록이 마지막 저장 상태와 다름

빈 새 노트에서 아무 입력도 하지 않았다면 dirty로 보지 않는다.

### 내부 이동 보호

다음 내부 이동에서 dirty 상태이면 앱 내부 확인 모달을 표시한다.

- 다른 노트 선택
- 새 노트 버튼 클릭
- 태그 모드 진입
- 현재 편집 화면을 벗어나거나 편집 대상을 바꾸는 모든 내부 이동

모달 문구:

- 제목: `저장하지 않은 변경사항이 있습니다`
- 본문: `이동하면 현재 작성 중인 내용이 사라집니다.`
- 버튼: `계속 이동`, `취소`

동작:

- `계속 이동`: 현재 편집 상태를 마지막 저장 상태로 초기화하고 이동한다.
- `취소`: 현재 편집 화면에 그대로 머문다.

### 브라우저 이동 보호

다음 브라우저 이동에서도 미저장 변경 경고를 제공한다.

- 새로고침
- 탭 닫기
- 다른 URL로 이동

처리:

- `beforeunload` 기본 경고를 사용한다.
- 브라우저 기본 문구는 커스터마이즈하지 않는다.
- 앱 내부 모달과 별개로 동작한다.

## 기존 노트 모드 UI

### 사이드바 상단 버튼

- 기본 노트 모드의 사이드바 상단에 `태그` 버튼과 `새 노트` 버튼을 나란히 둔다.
- `태그` 버튼은 `새 노트` 버튼의 좌측에 둔다.

### 노트 목록

- 기존 노트 목록 정렬 기준은 변경하지 않는다.
- 태그 저장으로 `updatedAt`이 바뀌는 경우 기존 정렬 규칙에 따라 자연스럽게 위치가 바뀔 수 있다.
- 노트 제목이 비어 있으면 `(제목 없음)`으로 표시한다.

## 태그 모드

### 모드 전환

`App`에서 내부 상태로 `notes` 모드와 `tags` 모드를 관리한다.

- 라우터는 도입하지 않는다.
- `/tags`, `/tags/:tag` 같은 URL 경로를 만들지 않는다.

모드:

- `notes`: 기존 노트 목록 사이드바와 메인 편집 화면
- `tags`: 기존 사이드바와 노트 목록을 숨기고 전체 화면을 태그 탐색 UI로 사용

### 태그 모드 진입

- `태그` 버튼 클릭 시 태그 모드로 진입한다.
- dirty 상태이면 미저장 변경 모달을 먼저 표시한다.
- 태그 모드 진입 직전의 선택 노트 상태를 기억한다.
- 태그 모드에 다시 진입할 때마다 태그 목록 초기 상태로 시작한다.
- 이전 검색어나 이전 태그 상세 상태를 복원하지 않는다.

### 노트로 돌아가기

- 태그 모드에는 `노트로 돌아가기` 버튼을 제공한다.
- 이전 선택 노트가 아직 존재하면 그 노트 선택 상태로 돌아간다.
- 이전 선택 노트가 없어졌다면 선택 없음 상태로 노트 모드로 돌아간다.
- 태그 모드를 종료하면 태그 검색어와 내부 상세 상태는 초기화한다.

### 태그 상세에서 노트 열기

- 태그 상세의 노트 카드를 클릭하면 태그 모드를 종료하고 해당 노트를 선택한다.
- 이때 `isCreating`은 항상 `false`로 설정한다.
- 태그 모드 진입 전에 이미 미저장 변경을 확인했으므로, 노트 카드 클릭 시 별도 미저장 변경 경고는 띄우지 않는다.
- 클릭 시점에 노트가 없으면 태그 상세에 머무르고 `노트를 찾을 수 없습니다`를 표시한다.
- 노트를 연 뒤에는 일반 노트 편집 흐름으로 전환한다.
- 태그 모드로 돌아가는 별도 히스토리나 링크는 제공하지 않는다.

## 태그 목록 뷰

### 화면 구성

- 화면 제목: `태그`
- `노트로 돌아가기` 버튼
- 검색 입력
- 태그 카드 그리드

검색 입력 placeholder:

```text
태그 검색
```

### 포커스

- 태그 목록 뷰 진입 시 검색 입력에 자동 포커스한다.

### 태그 카드

태그 카드는 작은 카드형 그리드로 표시한다.

카드 내용:

- 대표 태그명
- 포함 노트 수
- 최근 저장일

표시 예:

```text
React
3개 노트
최근 저장 2026.05.10 14:30
```

카드 동작:

- 카드 전체를 클릭 가능하게 한다.
- 클릭 시 해당 태그 상세 뷰로 이동한다.

카드 레이아웃:

- 모바일 1열
- 태블릿 2열
- 데스크톱 3열
- 최소 높이를 둔다.
- 긴 태그명은 최대 2줄까지 허용하고 말줄임 처리한다.

### 태그 목록 정렬

검색어가 없을 때:

- 최근 저장일 내림차순으로 정렬한다.
- 잘못된 날짜는 가장 오래된 값으로 취급한다.

검색어가 있을 때:

1. 짧게 일치하는 태그 우선
2. 길이가 같으면 최근 저장일 내림차순
3. 그래도 같으면 대표 표시명 가나다/알파벳 순

예:

- 검색어 `rea`
- `React`가 `React Query`보다 먼저 표시된다.

### 태그 검색

- 대표 표시명 기준으로 검색한다.
- 대소문자 무시 prefix 검색을 사용한다.
- `#`도 일반 문자로 prefix 매칭한다.
- 한글 초성 검색은 지원하지 않는다.
- 검색 입력의 `Escape`는 아무 동작도 하지 않는다.
- 검색 입력값이 있을 때만 작은 `x` 지우기 버튼을 입력창 안에 표시한다.
- `x` 지우기 버튼을 누르면 검색어를 비운다.
- 태그 목록 뷰에서만 검색 입력을 표시한다.
- 태그 상세 뷰에는 검색 입력을 표시하지 않는다.

### 빈 상태

태그가 하나도 없을 때:

- 제목: `아직 태그가 없습니다`
- 본문: `노트에 태그를 추가하면 여기에 표시됩니다.`
- `노트로 돌아가기` 버튼 제공

검색 결과가 없을 때:

- 태그 목록 영역 안에 `검색 결과가 없습니다` 문구만 표시한다.
- 검색 결과 없음 상태에 별도 `검색어 지우기` 버튼은 제공하지 않는다.

### 로딩과 오류

- 태그는 노트 데이터에서 파생되므로 기존 노트 로딩 상태를 공유한다.
- 노트 로딩 중이면 태그 화면에서도 동일한 로딩 UI를 보여준다.
- 기존 `error` 상태가 있으면 태그 모드 상단 또는 빈 상태 영역에 표시한다.
- 오류가 있어도 보유한 `notes` 상태가 있으면 태그 UI는 계속 렌더링한다.

## 태그 상세 뷰

### 화면 구성

- 화면 제목: 대표 태그명
- `태그 목록으로` 버튼
- `노트로 돌아가기` 버튼
- 노트 수
- 해당 태그가 붙은 노트 카드 목록

노트 수 표시:

```text
3개 노트
```

태그명은 `#` 접두어를 임의로 붙이지 않고 대표 표시명 그대로 보여준다. 대표 표시명 자체에 `#`가 포함되어 있으면 그 `#`는 그대로 표시한다.

### 내부 내비게이션

- 태그 목록 뷰에는 내부 뒤로가기 버튼을 두지 않는다.
- 태그 상세 뷰에는 `태그 목록으로` 버튼을 둔다.
- `태그 목록으로`는 태그 목록 뷰로 돌아간다.
- `노트로 돌아가기`는 태그 모드를 완전히 종료하고 노트 모드로 돌아간다.

### 검색어 유지

- 태그 목록에서 검색 후 태그 상세로 들어갔다가 `태그 목록으로` 돌아오면 검색어를 유지한다.
- `노트로 돌아가기`로 태그 모드를 종료하면 검색어를 초기화한다.

### 노트 목록 정렬

- 해당 태그가 포함된 노트들은 `updatedAt` 내림차순으로 정렬한다.
- 날짜 비교는 `Date`로 파싱해서 수행한다.
- 잘못된 날짜는 가장 오래된 값으로 취급한다.

### 노트 카드

노트 카드에는 다음 정보를 표시한다.

- 제목
- 본문 미리보기
- 최근 저장일
- 해당 노트의 전체 태그 칩

제목:

- 제목이 비어 있으면 `(제목 없음)`으로 표시한다.

본문 미리보기:

- 본문이 있으면 2줄 line-clamp로 표시한다.
- 본문이 비어 있으면 미리보기 영역을 숨긴다.

최근 저장일:

```text
최근 저장 YYYY.MM.DD HH:mm
```

- 날짜가 없거나 잘못된 경우에는 최근 저장 영역을 표시하지 않는다.

노트 카드 레이아웃:

- 모바일 1열
- 태블릿과 데스크톱 최대 2열
- 제목과 본문 미리보기가 충분히 보이도록 3열은 사용하지 않는다.

### 태그가 사라진 경우

태그 상세를 보고 있는 동안 해당 태그가 모든 노트에서 사라지면:

- 태그 목록 뷰로 자동 이동한다.
- `해당 태그가 더 이상 없습니다` 안내 메시지를 표시한다.

### 태그 상세 내 노트 검색

- 이번 범위에서는 제공하지 않는다.
- 추후 확장 기능으로 남긴다.

## API와 Context 규칙

- 컴포넌트는 `fetch`를 직접 호출하지 않는다.
- API 호출은 `src/api/notes.ts` 또는 `NotesContext` 액션을 통해 수행한다.
- CRUD 액션 이름은 기존과 같이 `createNote`, `updateNote`, `deleteNote`를 유지한다.
- API 모듈의 CRUD 함수도 동일한 동사 네이밍을 유지한다.
- 노트 생성/수정 시각은 `src/api/notes.ts`에서 요청 직전에 생성한다.
- API 요청 성공 후 응답 값을 기준으로 Context 상태를 갱신한다.
- API 요청 실패는 호출 지점에서 `console.error`로 기록하고, 필요한 경우 기존 `error` 상태로 화면에 노출한다.

- 날짜 비교와 표시 가능 여부 판단

### 컴포넌트 예상 분리

실제 파일명은 구현 시 기존 구조에 맞춰 조정할 수 있지만, 다음 책임 분리를 권장한다.

- `NoteEditor`: 태그 입력, 칩, dirty 계산, 저장 전 미추가 태그 모달 트리거
- `NoteItem`: 사이드바 노트 아이템의 태그 칩 표시
- `TagView` 또는 유사 컴포넌트: 태그 모드 최상위 화면
- `TagListView`: 태그 목록, 검색, 카드 그리드
- `TagDetailView`: 태그별 노트 카드 목록
- 공용 확인 모달 컴포넌트: 미저장 변경 모달과 미추가 태그 안내 모달에 사용

### App 상태

`App`은 다음 상태를 관리한다.

- 현재 모드: `notes` 또는 `tags`
- 태그 모드 내부 상태: 목록 또는 상세
- 선택된 태그 키
- 태그 모드 진입 직전 선택 노트 ID
- `NoteEditor`에서 전달받은 dirty 여부
- 미저장 변경 시 보류 중인 이동 액션

## 테스트 요구사항

### 태그 유틸 단위 테스트

다음을 검증한다.

- 앞뒤 공백 제거
- 내부 연속 공백 1칸 축약
- casing 유지
- 비교 키의 대소문자 무시
- `#`가 일반 문자로 포함됨
- `#React`와 `React`가 서로 다른 태그로 처리됨
- 허용 문자 검증
- ASCII 영문만 허용
- ASCII 숫자만 허용
- 완성형 한글 음절만 허용
- 최소 2자 검증
- 최대 20자 검증
- `#`은 길이 제한으로 거부되고 `##`은 허용됨
- `--`, `__`, `# #`이 허용됨
- 공백만 있는 입력이 무시됨
- 쉼표 분리와 빈 조각 무시
- 일괄 추가 중 하나라도 유효하지 않으면 아무 것도 추가하지 않음
- 입력 묶음 안의 중복 태그가 하나로 합쳐짐
- 현재 노트 내 중복 태그가 추가되지 않음
- 최대 5개 검사가 실제 추가될 태그 수 기준으로 수행됨
- 대표 표시명이 사용 빈도 기준으로 계산됨
- 대표 표시명 동률 시 최근 저장 표기를 사용함
- 대표 표시명 공백이 정규화됨
- 태그 집계에서 유효하지 않은 저장 태그를 무시함
- `updatedAt` 날짜 비교를 `Date` 파싱으로 수행함
- 잘못된 날짜를 정렬상 가장 오래된 값으로 취급함
- 태그 검색이 대소문자 무시 prefix 방식으로 동작함
- 태그 검색 중 짧게 일치하는 태그가 먼저 정렬됨
- 자동완성 후보가 최대 3개로 제한됨
- 자동완성 후보에서 현재 노트에 이미 있는 태그가 제외됨

### UI 흐름 테스트

React Testing Library와 Vitest를 우선 사용한다.

검증할 핵심 흐름:

- 노트 편집 화면에서 태그 입력 영역이 제목 아래, 본문 위에 표시됨
- 태그를 추가하면 칩으로 표시됨
- 태그 삭제 버튼으로 칩을 제거할 수 있음
- 태그 삭제 버튼이 키보드 focus로 접근 가능함
- 최대 5개 도달 시 입력 필드와 추가 버튼이 비활성화됨
- 태그 입력 오류가 인라인으로 표시됨
- 저장 시 미추가 태그 입력이 있으면 안내 모달이 표시되고 저장되지 않음
- 자동완성 후보가 최대 3개 표시됨
- 자동완성 후보 선택 시 즉시 칩으로 추가됨
- 자동완성에서 방향키, `Enter`, `Escape` 동작이 요구대로 동작함
- 저장 성공 후 태그 입력, 오류, 자동완성 상태가 초기화됨
- 저장 실패 시 입력값과 dirty 상태가 유지됨
- dirty 상태에서 다른 노트 선택, 새 노트, 태그 모드 진입 시 미저장 변경 모달이 표시됨
- 미저장 변경 모달에서 `계속 이동`을 누르면 변경사항을 버리고 이동함
- 미저장 변경 모달에서 `취소`를 누르면 현재 편집 화면에 머무름
- `beforeunload` 경고가 dirty 상태에서 등록됨
- 사이드바 노트 아이템에 태그 최대 2개와 `+N`이 표시됨
- 빈 제목이 `(제목 없음)`으로 표시됨
- 태그 버튼이 새 노트 버튼 좌측에 표시됨
- 태그 버튼 클릭 시 기존 사이드바가 숨겨지고 태그 모드 전체 화면이 표시됨
- 태그 목록 뷰 진입 시 검색 입력에 focus 됨
- 태그 카드에 태그명, `3개 노트`, `최근 저장 YYYY.MM.DD HH:mm`이 표시됨
- 태그 검색이 prefix 방식으로 동작함
- 검색 결과가 없을 때 `검색 결과가 없습니다`만 표시됨
- 검색 입력의 `x` 버튼으로 검색어가 초기화됨
- 태그 카드 클릭 시 태그 상세 뷰로 이동함
- 태그 상세에 대표 태그명, `3개 노트`, 노트 카드 목록이 표시됨
- 태그 상세 노트 카드에 제목, 본문 2줄 미리보기, 최근 저장일, 전체 태그 칩이 표시됨
- 본문이 비어 있으면 본문 미리보기 영역이 숨겨짐
- 태그 상세에서 `태그 목록으로`가 목록으로 돌아감
- 태그 상세에서 `노트로 돌아가기`가 노트 모드로 돌아감
- 태그 상세 노트 카드 클릭 시 `isCreating`이 false가 되고 해당 노트가 선택됨
- 태그 모드 종료 후 다시 진입하면 태그 목록 초기 상태로 시작함
- 태그 상세를 보고 있는 동안 태그가 사라지면 목록으로 이동하고 `해당 태그가 더 이상 없습니다`가 표시됨
- 클릭한 노트가 없으면 `노트를 찾을 수 없습니다`가 표시됨

### 검증 명령
